Generated by `analyze.py` after:

* **Rules**: 20 trials × {aura, python} × {filter on, off}
* **LLM**: 3 trials × {aura, python} × {filter on, off}  
  (MiniMax-M2.5 via `AURA_LLM_*` env)

## Proxy Lyapunov function

```
V = 10·test_fail + 2·recursive_residual + 0.1·node_count + 0.05·|Δnodes|
S = test_fail==0 ∧ recursive_residual==0 ∧ node_count ≤ 1.5·initial
```

Seed: recursive `fact`. Target: correct iterative `fact` inside S.

## Rules controller (clean comparison)

Both engines behave as a **strict Lyapunov step** under the shared rule set:

| engine | V₀ (approx) | V∞ | ΔV on accept | steps to S | succ% |
|--------|-------------|-----|--------------|------------|-------|
| Aura   | 3.70        | 2.75 | −0.95       | 1          | 100%  |
| Python | 4.50        | 2.95 | −1.55       | 1          | 100%  |

Interpretation:

* Seed recursive `fact` already **passes** `fact(10)` (thanks to #2292 fix), so the only residual is recursion.
* One accepted rewrite to GOOD-ITER drops `recursive_residual` 1→0 and lands in S.
* Filter **never rejects** the good rewrite (`ΔV < 0`), so filter on/off match.
* Aura’s final V is slightly lower (FlatAST node counts differ from CPython `ast`).
* **Oscillation count = 0** both sides — monotone decrease, no chatter.

This is the intended “stable controller” baseline: structured local action + ΔV
guard does not fight a correct proposal.

## LLM controller (noisy proposals)

| engine | filter | succ% | mean_k | notes |
|--------|--------|-------|--------|-------|
| Python | off/on | 100%  | ~2.3–2.7 | MiniMax produces valid Python; both reach S |
| Aura   | off    | 0%    | —     | Scheme proposals often wrong / timeout |
| Aura   | on     | 33%   | 2.0   | Snapshot+ΔV rejects some disasters (`rej%≈58%`) but one trial still exploded V |

Interpretation:

* Python LLM path is mature (model native language = Python).
* Aura LLM path is limited by **model Scheme quality**, not by the filter mechanics;
  when proposals are valid, filter-on can accept (trial 00 reached S with V∞=2.75).
* Extreme `min_Δ` / `mean_V∞` on Aura+filter-on come from a single bad install that
  temporarily bound a non-function / huge residual before restore — room to harden
  install validation further.

## How to reproduce

```bash
./build.py build
export AURA_PIPELINE_STRICT=0
TRIALS=20 ./demos/lyapunov-fact/run_all_rules.sh

# optional LLM
export AURA_LLM_API_KEY=... AURA_LLM_MODEL=MiniMax-M2.5 AURA_LLM_BASE_URL=https://api.minimax.chat/v1
python3 demos/lyapunov-fact/exp2_llm/run_python_llm.py --filter on --trials 10
python3 demos/lyapunov-fact/exp2_llm/run_aura_llm.py   --filter on --trials 10
python3 demos/lyapunov-fact/analyze.py
```
