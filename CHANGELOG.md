# Changelog

## Unreleased

- Perf/Stdlib (#5455): `std/schedule` kept every fired/cancelled timer in one list forever: `schedule:after` appended to it (O(n) per arm; 100 arms took 531 ms after 15k timers), `sched-timer` scanned it (O(n) cancel), and `schedule:pending` / `schedule:timers` mapped/filtered the whole history (33 ms / 263 ms after 15k). Timers now live in an id-keyed hash table: arm and lookup are O(1), and finished (`done`/`cancelled`) timers are reaped when their result is read — `schedule:timers` returns them once, `schedule:pending` reaps before scanning. Regression: `tests/suite/schedule.aura` (300 finished timers are reported once then leave the table; the following 100 arms stay flat). Bench: 150 × 100 one-ms timers, arm time stays 16–17 ms and final pending/timers are 0 (the report's 15100-retained case was 531 ms / 33 ms / 263 ms).
- Security/Stdlib (#5454): handler response headers were concatenated into the wire as `Name: value` with no validation, so a handler that echoed request data into a header (`Location`, `X-Request-Id`, CORS origin) could inject `\r\nInjected: yes` and additional headers/body prefix; header names were unchecked too. Response headers are now validated centrally before writing: names must be RFC token characters, values may contain HTAB/SP/visible/obs-text but no CTL or DEL, and any violation turns the response into `500 invalid response header` instead of emitting it. Regression: `tests/suite/webhook.aura` (CRLF in an echoed value and in a header name both answer 500 with no `Injected` line).
- Bug/Stdlib (#5453): `std/webhook` handed the handler every byte received in the same read as the body, not just `Content-Length` (`Content-Length: 5` + `helloEXTRA` reached the handler as `helloEXTRA`). It also parsed `Content-Length` with `string->number` + `wh-int ... 0`, so `abc`, `5, 5`, `0x10`, `5 5`, an empty value or a repeated header became a zero-length body and a `200`, and `1e1` waited for its read timeout. The header is now one strict 1*DIGIT value (repeats and comma lists are refused), invalid values answer `400 invalid content-length` immediately, and the body is cut at the announced byte count (extra bytes discarded; OWS around the header value is still accepted per HTTP). Regression: `tests/suite/webhook.aura` (overlong body truncation, zero-length discard, the invalid table, duplicate header, immediate `1e1` refusal).
- Bug/Stdlib (#5452): `webhook:stop!` inverted its "server fiber is gone" branch. When the server fiber had been cancelled (or crashed), `wh-await` timed out, nothing closed the listener, and a second 5 s wait for a stop reply that could never arrive made `stop!` take 10 s and return `#t` with the port still occupied. `stop!` now closes the listener itself when the close reply does not arrive (500 ms), skips the stop handshake, releases `running`, and lets the port be re-listened; on the normal path it no longer closes the listener a second time. Regression: `tests/suite/webhook.aura` (cancel the server fiber, stop under 2 s, re-listen the same port).
- Perf (#5451): `std/webhook` accepted at most one connection per 5 ms tick and the listener backlog was a fixed 16. An idle request paid up to 5 ms of accept latency, ~170 req/s was the ceiling, and a 100-connection burst stalled while 200 connections hit resets. The accept loop now drains every ready connection (up to 256 per tick, so control messages are still serviced) before a 1 ms idle tick, and `tcp-listen` uses `SOMAXCONN` instead of 16. Regression: `tests/suite/webhook.aura` (a 200-connection burst all answer `200`).
- Security/Stdlib (#5450): `std/webhook` read the request head and body without a total deadline; only the transport's per-`recv` 10 s `SO_RCVTIMEO` bounded a stalled peer. Sixteen idle partial-head connections held every `max-inflight` slot and every normal request got `503`, and a refusal closed the socket with unread request bytes, so a client saw `ECONNRESET` instead of the status line. The head and (separately) the body now run under `"read-timeout-ms"` (default 2000) and answer `408` on expiry; refusals (`408`/`413`/`431`/`501`/`503`) write the response, `shutdown(SHUT_WR)`, drain/discard the peer's remaining bytes for up to `"close-drain-ms"` (250 ms), then close. Two transport primitives back this: `tcp-recv-timeout` returns `'timeout` rather than conflating a deadline with EOF, and `tcp-close-graceful` does the shutdown/drain/close. Regression: `tests/suite/webhook.aura` (16 half heads each get a readable `408` and free the slots for a `200`; a stalled body gets `408`; a busy `503` is readable to its body).
- Perf (#5449): the scheduler's IO loop no longer scans `owned_fibers_` on every turn to find and expire timed-park deadlines. `Fiber::set_park_deadline_ms` publishes `(deadline, generation, fiber)` into a per-Scheduler min-heap; the loop peeks the single nearest deadline for its `epoll_wait` timeout and pops only the expired entries, dropping stale heads lazily. Retirement purges a fiber's entries before the object is destroyed, so a long-deadline entry cannot outlive its Fiber. The issue's storm of 8000 sleepers that all wait 100 ms finishes in ~3.4 s wall / 3.2 s CPU here (the report measured 21.3 s / 23.6 s). The wake/re-park increment itself is linear: 65 ms for 1000 sleepers, 112 ms for 2000, 208 ms for 4000 and 344 ms for 8000. Regression: `tests/suite/fiber_sleep_park.aura` (512 simultaneous sleepers wake exactly once).
- Perf (#5448): `std/webhook` no longer counts bytes with an interpreted per-code-point loop. New `string-byte-length` is an O(1) UTF-8 byte count over the string heap; the request reader collects chunks and concatenates once instead of re-appending and re-counting the whole body per chunk; `tcp-send` takes an optional byte offset so a partial send resumes without a byte-index walk or a substring copy. 64 KiB request and response now complete in milliseconds, and the request path is linear (the 1 MiB body path was 38.7 s). Regression: `tests/suite/webhook.aura` (128 KiB round trip) and `tests/suite/core.aura` (`string-byte-length`).
- Test (#5447): the offline LLM tests no longer inherit a real `llm-api-key` from the operator's default secret store. `_aura_test_env` and the process-test `run_llm_program` point `AURA_SECRET_STORE` at an empty 0700 temp directory; the two #5293 guards in `llm_safety.aura` now check both `LLM_API_KEY` and the store, and `test_module_require_freevar` AC2 sets an empty store around `llm-ask`. Regression: `llm_safety.aura` with a key in `$HOME/.aura/secrets` stays offline.
- Security (#5443): `llm:chat-vision` now runs `llm:injection-risk?` and `llm:sanitize-prompt` over the concatenation of every text part, not on each part in isolation. A marker split across two adjacent parts (`"ignore all previous "` + `"instructions..."`, or `<|im_` + `start|>`) is no longer an empty bypass; the sanitizer's boundary-spanning deletions are redistributed over the returned parts. Regression: `tests/suite/llm_multimodal.aura` (phrase and chat-tag split cases).
- Stdlib (#5445): `std/schedule` no longer loses an alarm past `fiber:sleep`'s 24 h ceiling. A longer `schedule:after` / `schedule:at` wait is split into chunks of at most 86400000 ms, re-reading the clock after each chunk, so a daily or weekly alarm fires on time instead of dying in the primitive's argument check. A timer-fiber failure is recorded on the timer as `state: "failed"` plus an `"error"` string, visible in `schedule:timers` and `schedule:pending`, instead of leaving an `armed` timer whose fiber is gone. Alarm files are written to a temp file in the same directory and renamed over the target with the new `file-rename` primitive, so a crash leaves the old JSON file or the new one, never a torn file. A bad alarm file now only costs itself: `schedule:open` skips it, still delivers every valid alarm, and names it in `(schedule:problems s)`; the file is left in place. Regression: `tests/suite/schedule.aura` (25 h and 86400001 ms waits, failed fiber state, torn and mismatched files beside a valid alarm) and `tests/suite/file-io.aura` (`file-rename`).
- Security (#5442): `std/secret` no longer falls back to `/tmp/aura-secrets` when neither `AURA_SECRET_STORE` nor `HOME` is set; `secret:default-store` returns `bad-store-path` and `std/llm` falls back to `LLM_API_KEY`. Reads now verify that the store directory is `0700`, the secret file is `0600`, and both are owned by the current uid; a wrong mode/owner, or a sandbox without the exec needed for `stat`, returns `secret-unavailable`. `secret:exists?`/`secret:list` and provisioning apply the same directory check. Regression: `tests/suite/secret.aura` (no-HOME default store, wrong directory mode, wrong file mode).
- Agent (#5441): the worker no longer turns an LLM failure into a completed task. `llm:chat` returns a structured `(ok content)` / `(error reason)`; a real failure calls `bus:fail` and exits the worker non-zero instead of shipping an `llm-error:` string as the answer. The lease is renewed by a heartbeat fiber at one third of `--lease-ms` while the model call runs, and once more before completion, so a slow call cannot lose the task. Contract evidence is no longer a constant: a real run requires the answer to cite the longest token of `--requirement` (and the worker now requires `--requirement` in real mode), failing as `verify:answer-misses:*` otherwise; `--mock` explicitly prints `verify=mock-unverified`. Regression: `test_bus_agents_e2e` (offline LLM failure → task failed, worker non-zero; 2 s model call with a 500 ms lease still completes) and the mock e2e path.
- Compiler (#5472): two fiber bodies in `mutate:rebind` could deadlock the process. A body reached the service mutation lock under the workspace lock or the IR cache gate (the rebind add-path's populate, set-code's pre-cache, `cache_define`'s redefine invalidate), while the post-boundary cascade drain took the mutation lock first and then waited for the workspace lock; the other bodies queued behind the workspace lock and the main thread on `fiber:join`, with no error and no timeout. The outermost `MutationBoundaryGuard` and `WorkspaceUniqueIfNeeded` take the mutation lock before the workspace lock now and hold it through the drain, and `populate_ir_cache_v2_from_workspace` / `unload_module` take it before the IR cache gate: the order is Mutate → Workspace → IR cache gate on every such path. Under 2 CPUs, the `test_fiber_hash_key_survives_rebind_4709` program hangs 0 times in 12000 runs with the JIT off and 300 with the JIT default (3/3000 on 0.3.3). Docs: `docs/stdlib/fiber-spawn.md`.
- Mutation (#5473): the evolution-log step that every `mutate:*` runs before entering the mutation boundary read the target define's source and the mutation id from the live workspace without a lock. Under concurrent rebinds that was a `FlatAST::set_loc` precondition abort or a SIGSEGV in the tag/arity index, about 0.02% of runs each. The read takes the shared workspace lock now, adopting a hold the thread already has. 0 crashes in the 12000 + 300 runs of the same stress.
- Mutation (#5475): the tail of `set-code` (the define re-bind, the revive re-parse, the epoch stamps) and the IR closure install of `mutate:rebind` ran after their boundary had ended, with no lock. A peer fiber's rebind on the same FlatAST / StringPool raced them: a hang in `StringPool::intern` with the pool lock held (the peer then blocks on its read lock, the main thread on `fiber:join`) or a SIGSEGV in `mark_dirty_upward`, 8 of 200 runs with one fiber reloading the workspace and another rebinding. Both take the eval-current shape now: the mutation lock, the exclusive workspace lock, and the pin that fail-closes a nested mutate. 0 hangs and 0 crashes in 1000 + 300 runs. Regression: `tests/python/process/reg_concurrent_rebind.py` (rebind add-path against rebind, reload against rebind, the four-body storm).
- Bus (#5440): a lost `.tasks.gates` no longer poisons the board forever. The fail-closed marker is persisted per task (`Lost` names its id); re-issuing the contract and approving it appends `Recovered`, so that task can be claimed and completed again, and the marker is not re-applied to new or gate-healthy tasks on later restarts. A corrupt ledger is replaced with a valid one carrying the per-task markers instead of leaving the host unable to persist gates. The global budget is re-evaluated against the current `AURA_BUS_*` limits at startup, so raising `AURA_BUS_GLOBAL_*` clears a stale trip; the global wall-clock limit is now a rolling window, so a host that has been up longer than the window starts a fresh one instead of staying tripped. Regression: `test_bus_tasks` (ledger loss → re-issue → two restarts, and raising the global limit) and `test_bus_budget`.
- Bus (#5439): a no-id `bus:claim` walks every open task in id order and skips the candidates whose gates refuse them (denied, pending or timed-out approval, lost gate ledger) instead of stopping at the oldest one; when open tasks exist but none can be claimed it returns `task-none-claimable` instead of `task-none-open`, so a blocked board is distinguishable from an empty one. A named claim keeps its specific refusal. The worker in `lib/std/bus_agent_cli.aura` now treats only `task-none-open` as idle and exits 0; contract/gate/budget/permission/transport claim errors print `claim-error=...` and exit non-zero, so a blocked board is no longer reported as a clean drain. Regression: the `bus_tasks` suite and `test_bus_agents_e2e`.
- Stdlib (#5416): `std/mcp`, a Model Context Protocol client over the stdio transport. `(mcp:client cmd [timeout])` runs one short-lived child per call: `initialize` + `notifications/initialized` + `tools/list` or `tools/call` are written as newline-delimited JSON-RPC and replies are matched by id; non-JSON lines are ignored. `mcp:list-tools` returns the tool list, `mcp:call-tool` the MCP result object, and `mcp:tool-names` is a convenience. Tool descriptions/results are ingested data and never become a capability or a grant; starting the child still needs `--grant exec`. Fixture and tests: `tests/fixtures/mcp_tool_server.py` and `tests/suite/mcp.aura`. Docs: `docs/stdlib/mcp.md`.
- Security (#5417): `std/secret`, a local minimal-disclosure credential store. Named values live in `$AURA_SECRET_STORE` (default `$HOME/.aura/secrets`), one base64 file per value with a `0700` directory and `0600` files; handles carry only the name/path. `secret:use` hands the plaintext to a callback and masks a string result with `***`, `secret:use-raw` is the explicit transport escape hatch, and `secret:redact`/`secret:contains-known?` mask values already seen. `secret:put!`/`import-file!`/`import-env!` provision (needs exec+write); reads need `io-read` and fail as `secret-unavailable` without naming a value. `std/llm` now reads `llm-api-key` from the store first and keeps `LLM_API_KEY` as a deprecated fallback. Docs: `docs/stdlib/secret.md`; tests: `tests/suite/secret.aura`.
- Stdlib (#5418): `llm:chat` accepts an OpenAI-compatible content-parts list for the user turn, and `llm:chat-vision` is the explicit entry point. `llm:text-part` / `llm:image-part` build `text` and `image_url` parts (data URL or http(s)); PNG/JPEG/GIF/WEBP are accepted and a data URL over the 10 MB image budget is refused as `image-too-large` before any bytes leave the process. Text parts keep the sanitizer/injection gate, `llm:parse-response` keeps the `truncated/finish=<reason>` behavior for reasoning-only replies, and `llm:chat-request` exposes the pure JSON body for tests. Live probe: MiniMax-M3.1-Flash accepted a PNG data URL. Docs: `docs/stdlib/llm.md`; tests: `tests/suite/llm_multimodal.aura`.

## 0.3.3

Unattended multi-agent delivery on the workspace bus: a durable task board with claims, leases, contracts, approvals and budgets, a planner/worker/supervisor CLI that runs the board end to end, and the production hardening that lets a supervisor survive a host crash and reclaim its work. Compiler and runtime pickups: IR specialization for loaded and variadic lambdas, `fiber:sleep`, `std/schedule`, `std/webhook`, the M4 live-fork surface, and external-only tracing. No new syntax. The API is still not stable.

- M4 (#5410): verified the live-process fork surface. `(mutate :snapshot ...)` is a workspace code checkpoint; it returns -1 with `:no-workspace` for file/-e top-level defines, and `ast:snapshot` is not a public binding (`mw:snapshot` is internal). The M4 fork API is the per-fiber COW overlay (`mutate :overlay-begin` / `:overlay-define` / `:overlay-set!` / `:overlay-get` / `:overlay-commit` / `:overlay-rollback`): N fibers mutate isolated worldlines, commit the winner and roll back the losers. Regression: `test_m4_5410_5412`.
- M4 (#5411): `mutate:rebind` installs the new define closure without `eval-current`, so counters, RNG, entities and open resources stay continuous in a long-running process; `std/hot-strategy:swap!`/`:heal!` no longer call `eval-current` for the same reason. A rejected rebind leaves the old body and state live. Regression: `test_m4_5410_5412`.
- M4 (#5412): `(current-source :workspace :preserve)` exports the set-code text with untouched comments/whitespace byte-identical after `mutate:rebind`; the rebind patches only the changed define body. Plain `(current-source :workspace)` stays the compact unparse view, and `:preserve` falls back to unparse when the source stamp is stale. Docs: `docs/m4-live-fork.md`. Regression: `test_m4_5410_5412`.
- M4 (#5413): the rehearsal search surface, two stdlib modules over algorithms main already has. `std/edit-search` searches AST edit sequences under a stage gate (an edit of stage s needs every earlier stage's contract met; `evaluate` reports `passed` / `ok`) with `prop:tree` as the engine (`"mcts"`, this module is its inner proposer) or the `std/search` beam (`"beam"`, the tree materialised one generation ahead, offer order or a prior); a broken candidate is ranked and never expanded, and the reserved `std/search` kinds (`mcts`, `cma-es`, `bayes-opt`) stay refused. `std/race` races fibers that already run: `race:halving` keeps the better half each round, `race:bandit` cuts an arm once its Hoeffding bound on "share of slots in the top half" is below another arm's; both `fiber:cancel` and join the losers and answer budget rows in the `std/portfolio` shape, and the bandit ledger is a `std/search` bandit. `std/search` gains `search:arms` (the bandit ledger as data) and loses a UCB bug: the pick leaked a `(score . arm)` pair after the first pass over the arms, freezing the ledger at one pull per arm. Docs: `docs/stdlib/edit-search.md`. Regression: `tests/suite/edit_search.aura`, `tests/suite/fiber_race.aura`, the `search_clonal` suite.
- Compiler (#5420, #5421): top-level defines from file, `load`, `require` and `-e` publish their IR closures before later forms run, and a module disk-cache hit binds the cached IR closure into the module env, so hot recursion in those faces reports `ir-calls=2000003, tw-calls=3` instead of staying on the tree walker. The IR interpreter now packs dotted-rest arguments into a pair list on every call path (closure call, direct call, `apply`, `execute_function`), matching the #5222 JIT, so variadic hot functions specialize too (`ir-calls=800004, tw-calls=3` for a variadic fixed-vs-rest loop); the #4621 rest specialization gates are gone. Regression: `tests/suite/core.aura` and the module batch.
- Runtime (#5414): `(fiber:sleep ms)` is the kernel wait. A scheduler fiber that may park goes `Waiting` with a park deadline the IO loop honours (its worker stays free); anything else sleeps the OS thread in slices of at most 20 ms. The wait is a cancellation safepoint: a parked sleeper is nudged at once, a slice sleeper answers within its slice. `Scheduler::run` no longer counts a tick that saw an armed park deadline as idle, which used to abandon a sleep longer than the idle window. New `std/schedule`: `schedule:after` / `schedule:at` run a thunk once on their own fiber and `schedule:cancel` stops it; with a directory each alarm is one JSON file (written when armed, rewritten `fired` before the handler runs, deleted after it returns), so `(schedule:open DIR (hash "on-due" fn))` hands the overdue and the `fired` alarms to `fn` once and re-arms the rest, a file that is not an alarm is a refusal, and `schedule:shutdown` stops the fibers but keeps the files. `orch-wait-sec`, the `orch:ask` poll, the `std/portfolio` watchdog and the `std/race` default wait moved from yield loops onto the sleep. The fast loop (`tests/run.py affected`) now starts a `;; suite-mode: serve-async` file the way the suite runner does. Docs: `docs/stdlib/fiber-sleep.md`. Regression: `tests/suite/fiber_sleep_park.aura` (serve-async), `tests/suite/schedule.aura`, the `issue_5064_fiber_cancel_text` suite.
- Stdlib (#5415): `std/webhook`, an inbound HTTP server in Aura over the `tcp-*` transport. `(webhook:make opts)` with routes (`webhook:route! s path methods handler`), a body limit (413 as soon as the head announces more), a header limit (431), a bound on in-flight requests (503 beyond it); each request is handled on its own fiber so the accept loop keeps serving, and the server fiber and the handlers sleep between steps, so `fiber:cancel` reaches them. Authentication is an explicit hook; with no hook reads pass and every write is refused 401 unless the route says `"public" #t`; `webhook:token-auth` compares a Bearer token without an early exit. Counters are atomic and the audit trail is the server fiber's, queried through the control channel and kept by `webhook:stop!`. The health listener stays separate: `webhook:make` refuses the health port and `/healthz`, `/readyz`, `/metrics` are refused as routes and answered 404. Thread backend only (under `--serve-async` the `tcp-*` primitives block the worker), needs `--grant net`, stop it before the process exits. Docs: `docs/stdlib/webhook.md`. Regression: `tests/suite/webhook.aura`.
- Observability (#5409): external-only tracing for the aura binary. Release/nightly/CI builds keep frame pointers (`-fno-omit-frame-pointer`, plus the x86 leaf-frame flag) so `perf -g` and eBPF `ustack()` can walk native stacks; `-rdynamic` now exports the interpreter/runtime symbols even without LLVM. `AURA_PERF_MAP=1` writes the standard `/tmp/perf-<pid>.map` with `Lisp:<name>` entries for every JIT-compiled function, so stock perf and FlameGraph name Lisp frames. Zero-cost USDT probes (`aura:fiber__spawn`, `fiber__yield`, `fiber__resume`, `channel__wait_enter`/`exit`, `gc__start`/`end`, `http_post__start`/`end`, `require_eval__start`/`end`) are emitted into `.note.stapsdt`; without a tracer they are one NOP. Regression: `test_observability_5409` (perf map contents and opt-in behavior, probe notes, exported symbols).
- Bus (#5423): production hardening for the supervisor. `bus:supervise` now returns `open-tasks`, and the supervisor targets `min(capacity, alive + open-tasks)` — capacity alone no longer starts an idle worker loop; work arriving later wakes it. The host survives a crash: `listen_at` takes a cross-process `flock` beside the socket, probes an existing node (a live listener is refused, a stale `ECONNREFUSED`/`ENOENT` node is unlinked) and only unlinks a real socket it owns, so a new host can take over the same workspace and the task board resumes. The supervisor reconnects with 1s→30s backoff after a host EOF/restart, keeps its children, and only exits on an `attach rejected` (role/workspace/schema). SIGTERM drains active workers for `--drain-ms` (default 10000) before SIGTERM/SIGKILL. The per-worker estimate is tunable with `AURA_SUPERVISOR_RESERVE_MB`, `AURA_SUPERVISOR_PER_WORKER_MB` and `AURA_SUPERVISOR_PER_WORKER_CPU_PCT` (zero/invalid values keep the defaults). `test_bus_repro` now runs with the source root as its ctest working directory, so the bus ctest set is 31/31. Regressions: `test_bus_agent_spawn` (no-work zero spawn, late-work spawn, SIGKILL host takeover + reconnect, SIGTERM drain) and `test_bus_supervisor` (policy knobs).
- Bus (#5424): gate fingerprints and candidate hashes are truncated to the 62-bit immediate domain at creation and masked on every read-back, so `bus:audit-replay` no longer aborts with a `make_int` contract failure on a full 64-bit value; `bus:gate-evidence` reports `adjusted=0` when no verdict exists instead of leaking the uninitialized bias. Manual replay: `gate-evidence`, `bus:repro` and `audit-replay` agree on fingerprint `739088533916224460`, findings 0.
- Bus (#5425): `channel_commit` and `audit_append` use incremental FNV digests over appended bytes, and worldline reprojection uses a record index instead of replaying the log, removing the O(N²) publish path. The SLO lane is widened to 20k records and asserts the cohort cost slope: measured ~1.26M records/CPU-s and 11% first-to-last growth (target <20%).
- Bus (#5426): the peer frame burst bucket defaults to the delivered image's channel capacity (an explicit `AURA_BUS_PEER_BURST` still wins), and an exhausted bucket sends an explicit rate-limit error frame before the session is cut. The default 256 MiB image sustained 100k publishes / 200k frames without a cut.
- Bus (#5427): contracts, approvals and budgets are appended to `.tasks.gates` beside the task board checkpoint and replayed on host restart, so a restored task keeps its contract, approval state and budget ledger; when the ledger is missing the restored task fails closed (durable Lost marker) instead of completing on zero evidence. Regression covers restart, budget persistence and zero-evidence completion refusal.
- Bus (#5428): `capacity-plan` reports remaining source slots/bytes and counts the string table in `rounds` and `low`; string-table append errors are shortened to fit `ErrorBody` and name the remaining capacity (`0/1024 left`). Test fills all 1024 slots.
- Bus (#5422): the supervisor's execution layer. `aura agent --role supervisor --spawn` attaches as role 6, asks the host for `bus:supervise` on an interval, and starts/stops `aura agent --role worker` processes to match the plan. There is no fixed total cap — only `--spawn-batch` (default 4) per cycle and `--interval-ms` (default 1000) against a fork storm. A shrink never kills an active worker; it stops replacing it and lets the lease drain. Workers get `PR_SET_PDEATHSIG(SIGTERM)` so a dead supervisor leaves no orphans; SIGINT/SIGTERM stops spawning, forwards SIGTERM and SIGKILLs after 5s. The host audits the action, not just the decision: `SupervisorPlan` (48) still records the worker count/reason, while `SupervisorSpawn` (49) and `SupervisorShrink` (50) record the started/stopped counts and the live count after the cycle (new write-only `SupervisorNote` frame). `--spawn-once` runs one cycle and waits, for CI. Regression: `test_bus_agent_spawn` (fixture slack admits 2, two workers drain 3 tasks, spawn audit records 2/live 2; low fixture admits 0, spawns nothing, plan reason 3).
- Bus (#5400): the planner/worker/supervisor roles and `aura agent`. Roles `4 planner`, `5 worker` and `6 supervisor` join the workspace policy (still hints: the preset and grants decide; unknown roles are denied). `aura agent --role …` resolves and runs `lib/std/bus_agent_cli.aura`: a planner posts tasks (optionally approval-gated contracts), a worker loops claim → `llm:chat` (or `--mock`) → heartbeat → contract evidence → complete/fail until the board drains, and a supervisor asks the host for its scaling plan. `--mock` is deterministic, network-free and key-free; a real run names `--prompt FILE`, so no prompt body is hardcoded. The host's `bus:supervise` measures its own CPU/memory slack (MemAvailable, idle `/proc/stat`), admits as many workers as actually fit with no fixed cap, and audits every decision as `SupervisorPlan` (48: worker count in version, reason in result). Fixtures `AURA_SUPERVISOR_MEM_FREE_MB` / `AURA_SUPERVISOR_CPU_FREE_PCT` / `AURA_SUPERVISOR_CPUS` pin the capacity in CI. Also fixes a latent #5402 crash: the contract fingerprint is a full 64-bit FNV hash, but it was passed to `make_int` (62-bit); the list surface now keeps its low 62 bits. Regression: `test_bus_supervisor`, the `bus_agents` suite, and `test_bus_agents_e2e`.
- Test (#5406): the multi-agent e2e lane with a mock LLM. One host, one planner, four mock workers and an approval script run the full contract-approved path (posted → approved → claimed → completed → contract gate) with no network and no key; the audit replay reconstructs the timeline with zero findings. ## 0.3.2

Autonomous performance-optimization loop: the bus now judges the statistics itself, so a KEEP is not a judge's promise but a recomputed result. No new syntax. The API is still not stable.

- Bus (#5391): the statistical admission contract, busified. A judge binds the held-out evidence of a candidate to its trial — `bus:bind-gate` carries the per-fold out-of-sample metric deltas in parts per million, the round the candidate belongs to, and the tie to the evidence five-tuple (workload, seed, verifier). The coordinator does not take the judge's word for it: it recomputes the mean, the sample standard deviation and the standard error from the bound windows, applies the Bailey/López-de-Prado haircut (`E[max of N normals] * se`, the same math as `std/validation`'s `val:deflate`) for the family it observed itself, and decides. A KEEP without statistical evidence is refused `missing-gate-evidence`; a round without a negative control is refused `missing-negative-control`; a negative control the statistics accept is a gate failure (`negative-control-accepted`); a control is never applied (`negative-control-refused`); a candidate the statistics reject never reaches the live workspace (`gate-rejected`). The verdict is fixed point, so the same evidence always reproduces the same record byte for byte, and it travels with the worldline record in a new additive tail (`gate_verdict`, `gate_family`, `gate_adjusted_ppm`, `gate_threshold_ppm`, `gate_fingerprint`) under layout_version 3 — a v1 or v2 image stays readable and the tail defaults to zero. The negative-KEEP budget watches the recent KEEPs: a reverted KEEP (or an accepted control) over the budget doubles the haircut multiplier and writes a `GateTighten` audit. New surface: `bus:bind-gate`, `bus:gate-evidence`, the `GateBind` frame, the `GateBind`/`GateVerdict`/`GateTighten` audit kinds, and the host env `AURA_BUS_GATE=1` (plus `AURA_BUS_GATE_THRESHOLD`, `AURA_BUS_GATE_MIN_WINDOWS`, `AURA_BUS_GATE_BUDGET`, `AURA_BUS_GATE_WINDOW`, `AURA_BUS_GATE_CONTROL`). Off by default, so the v0.3.1 surface is unchanged. Regression: `test_bus_stat_gate` (the statistics, the family correction, the refusals, the tightening, the additive layout, and the std/bus surface end to end through a real aura process).
- Bus (#5392): audit replay and deterministic reproduction. `bus:audit-replay` reconstructs the worldline lineage from the control-plane log and the image and checks its integrity: no orphan event (an event naming a worldline that was never opened), no broken parent chain, a monotonic audit sequence, the image audit section agreeing with the control log, and every KEEP carrying its constraint result and its admission verdict. The replay also reproduces the admission verdict: it recomputes it from the bound evidence with the policy snapshot the verdict was made under and compares byte for byte, and it recomputes the candidate hash from the trial's patch bytes — a tampered hash or a tampered verdict is caught. `bus:audit-evo` renders the same lineage as evo schema v2 JSONL, so `aura evo log` reads the bus closed-loop log directly. The replay is a read: it changes nothing. Regression: `test_bus_audit_replay` (a sound lineage replays clean, an orphan event / a broken parent / a sequence regression / an audit mismatch / a missing verdict are each found and localized, the adjudication reproduces byte for byte, a tampered candidate hash and a tampered verdict are caught, and the std/bus surface end to end through a real aura process).
- Bus (#5393): the admission round state machine. One round at a time, host-driven: `idle → signal → trial → judge → canary → sealed`, every transition audited (`RoundOpen`/`RoundTrial`/`RoundJudge`/`RoundSeal`/`RoundRoll`/`RoundBudget`/`RoundResume`). The peers propose and adjudicate; the host decides when a round starts and ends: `bus:round-open` is refused while a round is active, while an observation is unsealed, during the cooldown or under the round cap. Every failure fails closed — a judge that dies rolls its pending candidate back (`judge gone`), a proposer that dies reclaims its trial (`proposer gone`), a round that runs out of wall clock is closed automatically, and a reverted observation rolls its round back. The host checkpoints the round and the sealed candidates next to its socket, so a restarted host resumes (the round counter continues) and never applies a sealed candidate twice (`already-sealed`); the candidate identity is its *content* digest (the patch targets plus the source texts), not the patch bytes — the latter carry a string-table index that is not stable across hosts. New surface: `bus:round-open`, `bus:round-state`, `bus:round-budget`, the `RoundOpen`/`RoundQuery` frames and the host env `AURA_BUS_ROUND_WALL_MS`, `AURA_BUS_ROUND_COOLDOWN_MS`, `AURA_BUS_ROUND_MAX`. Regression: `test_bus_round_orchestration` (a normal round walks the phases and audits them, a judge that dies rolls the candidate back and the next round starts, a proposer that dies returns the round to idle, the wall budget closes a round, an unsealed observation refuses a new round, and a restarted host resumes without applying a sealed candidate twice).
- Bus (#5394): the host's degradation detector. The host watches a few key metrics on the metrics channel and runs an EWMA plus a one-sided CUSUM change test on them; the score is normalized by the metric's own magnitude, so the thresholds are unit free and the arithmetic is integer — the same samples always give the same verdict. A sustained degradation opens an admission round on its own (the round machine's signal state), and while a canary observation runs the same detector decides whether the candidate degraded the metric it was supposed to improve, rolling the observation back. False triggers are bounded by a minimum observation window and a hysteresis: after an alert the metric must return to its baseline (the change score back to zero) before the key may alert again, so a stationary load never opens a round. The configuration is versioned — installing one or rolling the previous one back needs constraint-write and is audited with its version (`DegradeConfig`), and every alert is audited (`DegradeAlert`). New surface: `bus:degradation-state`, `bus:degrade-install`, `bus:degrade-rollback`, the `DegradeQuery`/`DegradeConfig` frames and the host env `AURA_BUS_DEGRADE_KEYS`, `AURA_BUS_DEGRADE_UP`, `AURA_BUS_DEGRADE_MIN_SAMPLES`, `AURA_BUS_DEGRADE_ALPHA`, `AURA_BUS_DEGRADE_DRIFT`, `AURA_BUS_DEGRADE_LIMIT`, `AURA_BUS_DEGRADE_CALM`. Without watched keys the detector stays quiet and the host behaves exactly as in v0.3.1. Regression: `test_bus_degradation_trigger` (the detector itself, a phase shift that opens a round, a stationary load that does not, the versioned configuration and its audit) plus a case in `test_bus_canary_rollback` (a degradation during the observation rolls the candidate back).
- Bus: three contract regressions from v0.3.1 are green again. The image fixtures still laid the string table out as 48 bytes, but #5378 reserves a fixed 16 KiB entry array and puts the string bytes behind it, so `test_bus_image` and `test_bus_channels` no longer validate their own images; `test_bus_capability` still expected a scoped grant to refuse a read, but #5377 deliberately lets a scoped keep+rollback read the image and the audit.
- Bus (#5395): the bus's own performance counters and capacity plan. The coordinator measures its own cost in CPU time (the coordinator thread's `CLOCK_THREAD_CPUTIME_ID`, never the wall clock — on a shared runner the wall clock measures the scheduler, not the work, #5324): the frames served, the total and p99 per-frame CPU cost, the publishes and their CPU cost, the handshakes and their CPU cost, the catchup increments, and the loans and pending trials a peer would see. `bus:slo` reads the counters, `bus:capacity-plan` reads the room left in the image and the rounds it still supports — the channel capacities are a function of the delivered image (#5387), so the plan follows the image, and the plan flags a low room. New surface: the `SloQuery` frame, the `SloReplyBody`/`SloQueryBody` wire structs, src/bus/slo (the counters and the histogram) and the host env `AURA_BUS_ROUND_WALL_MS`-style knobs are unchanged. Regression: `test_bus_slo` (the p99 histogram, the capacity plan on a small image, and the std/bus surface end to end through a real aura process).
- Test (#5395): the bus SLO and soak lanes. `tests/bench/bus_slo.py` drives a resident host through a fixed traffic pattern and checks the versioned targets (the per-frame p99, the publish rate per CPU second, the largest catchup increment, the handshake cost and the capacity) in CPU time; `tests/bench/bus_soak.py` samples the resource curves (the host's RSS, its descriptors, the coordinator's committed bytes, the loans and the pending trials) while the rounds land, kills the worker periodically to prove the loop recovers and leaves no residue, and fails when a curve grows. The weekly lane (`.github/workflows/bus-soak-weekly.yml`) runs the SLO and then the soak for 24 hours.
- Bus (#5397): the target extension and the reproduction package. A candidate may now rewrite two or three pure policy functions at once (choose-fn + admit-fn + ttl-fn): the peer asks the host for its define names and node ids with `bus:defines` (the node ids live in the host's own workspace AST, so guessing them from another process is not sound), publishes one source-carrier patch per function into a single worldline, and the host's KEEP applies the set atomically — one broken body anywhere in the set leaves every function byte-identical. The host declares which functions the loop may evolve with `AURA_BUS_MUTABLE_TARGETS`; a target outside the list is refused like any other. Every KEEP's admission decision now leaves a reproduction package (`bus:repro`): the evidence five-tuple, the held-out windows, the policy snapshot and the coordinator's own verdict, as one JSON line. `aura bus-repro FILE` re-runs the decision offline — the same binary, the same gate math, no coordinator and no live bus — and compares it field by field; a tampered window fails the check. Regressions: `test_bus_multi_target` (three functions in one worldline, the all-or-nothing failure, the allowlist), `test_bus_repro` (the package reproduces; a tampered one does not).
- Bus (#5396): the adversarial peer boundaries. A hostile peer must not take the bus down and must not borrow authority from it; the rule is that the offending session is cut off and the others are untouched. A connection that never says hello is dropped at its handshake deadline (the coordinator's poll wakes for it instead of waiting for another peer's event). A session that floods the control plane is cut off at its frame rate quota — a token bucket (a sustained rate plus a burst deep enough for a legitimate bulk publish, so publishing the delivered image's channels in one go is not a false positive). The grant tree is bounded — depth 4, fanout 16, 32 live grants per session — so a peer cannot hand out authority in bulk, and a refused grant is audited on its own. `constraint-write` sessions have a change quota per window, and the constraint set now remembers who installed each rule: an install or a rollback that would drop a rule another session installed is refused (`would relax the protection set`), while a session may still roll back its own rules. Malformed frames — an unknown type, an illegal channel, a truncated body, an oversized length — are digested safely: the host does not crash and the honest peers do not notice. New audit kinds: `RateLimited` (29), `GrantLimited` (30). Host environment: `AURA_BUS_PEER_FRAMES` (the sustained rate), `AURA_BUS_PEER_BURST` (the bucket depth), `AURA_BUS_PEER_HELLO_MS`, `AURA_BUS_PEER_CONSTRAINT_CHANGES`, `AURA_BUS_PEER_CONSTRAINT_WINDOW_MS`. Regression: `test_bus_adversarial_peer` — one honest session attached before the attacks keeps answering through every one of them.
- Test: the bus harness reads exactly up to its marker. One pipe read can carry several lines, and the old reader dropped everything past the marker — so a reply that arrived in the same chunk as the previous one was lost, and the check failed depending on the timing (about one run in eight). The reader now keeps the bytes past the marker for the next read. The coordinator also stops only on a stop() request: the wake bell is a wakeup, not an exit, so a stray write can no longer take the bus down.
