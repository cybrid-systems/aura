# Changelog

## Unreleased

- Bus (#5399): the task board. A sixth channel, `tasks`, carries the append-only board events (`TaskRecord`), and `bus:post-task` / `bus:claim` / `bus:heartbeat` / `bus:complete` / `bus:fail` / `bus:task-status` drive them. A claim is atomic: a second claim while the lease is live is refused `task-claimed`, a non-holder heartbeat/complete is refused `task-not-owner`, and a lease that expires (or a clean `bus:detach`) puts the task back to open so another worker can claim it. The board is checkpointed next to the socket and `bus:unhost`/`bus:host` resumes open/claimed tasks instead of losing them. The channel is additive outside the frozen header schema: a v0.3.2 reader skips the unknown section, while a current reader validates it. Regression: `test_bus_tasks` and the `bus_tasks` suite.
- Bus (#5407): `bus:subscribe` now refuses an unknown channel with the same `permission/unknown channel` error as `bus:query`; before, it leaked the request bytes as a `Credit` and the client reported `validation-failed/malformed subscribe reply`.
- Bus (#5404): the human approval point. `bus:approve` requests (decision 0), approves (1) or denies (2) an object id; a pending approval times out to denied (state 3), and the audit carries request/grant/deny/timeout. A task posted with flag bit 0 (`kTaskNeedsApproval`) starts as a pending approval and `bus:claim` refuses it (`contract-approval-pending`, `contract-approval-timeout`, `contract-denied`, `contract-unapproved`) until approved. New capability bit `approve`; `bus:post-task` takes an optional flags word. Regression: `test_bus_approval` and the `bus_tasks` suite.
- Bus (#5401): `target-allowlist` and `metric-floor-bound` are fail-closed and parameterized by the install source. An empty or malformed source refuses; `target-allowlist` takes a comma/space-separated node-id list and only inspects source-carrier patches, while `metric-floor-bound` takes a numeric floor and refuses a lower `new_value`. `bus:grant` gains an optional task id and `bus:trial` carries it; a task-scoped capability may only open, keep and roll back that task's trial (`capability is scoped to another task`). Regression: `test_bus_constraint_defaults`.

## 0.3.2

Autonomous performance-optimization loop: the bus now judges the statistics itself, so a KEEP is not a judge's promise but a recomputed result. No new syntax. The API is still not stable.

- Bus (#5391): the statistical admission contract, busified. A judge binds the held-out evidence of a candidate to its trial — `bus:bind-gate` carries the per-fold out-of-sample metric deltas in parts per million, the round the candidate belongs to, and the tie to the evidence five-tuple (workload, seed, verifier). The coordinator does not take the judge's word for it: it recomputes the mean, the sample standard deviation and the standard error from the bound windows, applies the Bailey/López-de-Prado haircut (`E[max of N normals] * se`, the same math as `std/validation`'s `val:deflate`) for the family it observed itself, and decides. A KEEP without statistical evidence is refused `missing-gate-evidence`; a round without a negative control is refused `missing-negative-control`; a negative control the statistics accept is a gate failure (`negative-control-accepted`); a control is never applied (`negative-control-refused`); a candidate the statistics reject never reaches the live workspace (`gate-rejected`). The verdict is fixed point, so the same evidence always reproduces the same record byte for byte, and it travels with the worldline record in a new additive tail (`gate_verdict`, `gate_family`, `gate_adjusted_ppm`, `gate_threshold_ppm`, `gate_fingerprint`) under layout_version 3 — a v1 or v2 image stays readable and the tail defaults to zero. The negative-KEEP budget watches the recent KEEPs: a reverted KEEP (or an accepted control) over the budget doubles the haircut multiplier and writes a `GateTighten` audit. New surface: `bus:bind-gate`, `bus:gate-evidence`, the `GateBind` frame, the `GateBind`/`GateVerdict`/`GateTighten` audit kinds, and the host env `AURA_BUS_GATE=1` (plus `AURA_BUS_GATE_THRESHOLD`, `AURA_BUS_GATE_MIN_WINDOWS`, `AURA_BUS_GATE_BUDGET`, `AURA_BUS_GATE_WINDOW`, `AURA_BUS_GATE_CONTROL`). Off by default, so the v0.3.1 surface is unchanged. Regression: `test_bus_stat_gate` (the statistics, the family correction, the refusals, the tightening, the additive layout, and the std/bus surface end to end through a real aura process).
- Bus (#5392): audit replay and deterministic reproduction. `bus:audit-replay` reconstructs the worldline lineage from the control-plane log and the image and checks its integrity: no orphan event (an event naming a worldline that was never opened), no broken parent chain, a monotonic audit sequence, the image audit section agreeing with the control log, and every KEEP carrying its constraint result and its admission verdict. The replay also reproduces the admission verdict: it recomputes it from the bound evidence with the policy snapshot the verdict was made under and compares byte for byte, and it recomputes the candidate hash from the trial's patch bytes — a tampered hash or a tampered verdict is caught. `bus:audit-evo` renders the same lineage as evo schema v2 JSONL, so `aura evo log` reads the bus closed-loop log directly. The replay is a read: it changes nothing. Regression: `test_bus_audit_replay` (a sound lineage replays clean, an orphan event / a broken parent / a sequence regression / an audit mismatch / a missing verdict are each found and localized, the adjudication reproduces byte for byte, a tampered candidate hash and a tampered verdict are caught, and the std/bus surface end to end through a real aura process).
- Bus (#5393): the admission round state machine. One round at a time, host-driven: `idle → signal → trial → judge → canary → sealed`, every transition audited (`RoundOpen`/`RoundTrial`/`RoundJudge`/`RoundSeal`/`RoundRoll`/`RoundBudget`/`RoundResume`). The peers propose and adjudicate; the host decides when a round starts and ends: `bus:round-open` is refused while a round is active, while an observation is unsealed, during the cooldown or under the round cap. Every failure fails closed — a judge that dies rolls its pending candidate back (`judge gone`), a proposer that dies reclaims its trial (`proposer gone`), a round that runs out of wall clock is closed automatically, and a reverted observation rolls its round back. The host checkpoints the round and the sealed candidates next to its socket, so a restarted host resumes (the round counter continues) and never applies a sealed candidate twice (`already-sealed`); the candidate identity is its *content* digest (the patch targets plus the source texts), not the patch bytes — the latter carry a string-table index that is not stable across hosts. New surface: `bus:round-open`, `bus:round-state`, `bus:round-budget`, the `RoundOpen`/`RoundQuery` frames and the host env `AURA_BUS_ROUND_WALL_MS`, `AURA_BUS_ROUND_COOLDOWN_MS`, `AURA_BUS_ROUND_MAX`. Regression: `test_bus_round_orchestration` (a normal round walks the phases and audits them, a judge that dies rolls the candidate back and the next round starts, a proposer that dies returns the round to idle, the wall budget closes a round, an unsealed observation refuses a new round, and a restarted host resumes without applying a sealed candidate twice).
- Bus (#5394): the host's degradation detector. The host watches a few key metrics on the metrics channel and runs an EWMA plus a one-sided CUSUM change test on them; the score is normalized by the metric's own magnitude, so the thresholds are unit free and the arithmetic is integer — the same samples always give the same verdict. A sustained degradation opens an admission round on its own (the round machine's signal state), and while a canary observation runs the same detector decides whether the candidate degraded the metric it was supposed to improve, rolling the observation back. False triggers are bounded by a minimum observation window and a hysteresis: after an alert the metric must return to its baseline (the change score back to zero) before the key may alert again, so a stationary load never opens a round. The configuration is versioned — installing one or rolling the previous one back needs constraint-write and is audited with its version (`DegradeConfig`), and every alert is audited (`DegradeAlert`). New surface: `bus:degradation-state`, `bus:degrade-install`, `bus:degrade-rollback`, the `DegradeQuery`/`DegradeConfig` frames and the host env `AURA_BUS_DEGRADE_KEYS`, `AURA_BUS_DEGRADE_UP`, `AURA_BUS_DEGRADE_MIN_SAMPLES`, `AURA_BUS_DEGRADE_ALPHA`, `AURA_BUS_DEGRADE_DRIFT`, `AURA_BUS_DEGRADE_LIMIT`, `AURA_BUS_DEGRADE_CALM`. Without watched keys the detector stays quiet and the host behaves exactly as in v0.3.1. Regression: `test_bus_degradation_trigger` (the detector itself, a phase shift that opens a round, a stationary load that does not, the versioned configuration and its audit) plus a case in `test_bus_canary_rollback` (a degradation during the observation rolls the candidate back).
- Bus: three contract regressions from v0.3.1 are green again. The image fixtures still laid the string table out as 48 bytes, but #5378 reserves a fixed 16 KiB entry array and puts the string bytes behind it, so `test_bus_image` and `test_bus_channels` no longer validate their own images; `test_bus_capability` still expected a scoped grant to refuse a read, but #5377 deliberately lets a scoped keep+rollback read the image and the audit.
- Bus (#5395): the bus's own performance counters and capacity plan. The coordinator measures its own cost in CPU time (the coordinator thread's `CLOCK_THREAD_CPUTIME_ID`, never the wall clock — on a shared runner the wall clock measures the scheduler, not the work, #5324): the frames served, the total and p99 per-frame CPU cost, the publishes and their CPU cost, the handshakes and their CPU cost, the catchup increments, and the loans and pending trials a peer would see. `bus:slo` reads the counters, `bus:capacity-plan` reads the room left in the image and the rounds it still supports — the channel capacities are a function of the delivered image (#5387), so the plan follows the image, and the plan flags a low room. New surface: the `SloQuery` frame, the `SloReplyBody`/`SloQueryBody` wire structs, src/bus/slo (the counters and the histogram) and the host env `AURA_BUS_ROUND_WALL_MS`-style knobs are unchanged. Regression: `test_bus_slo` (the p99 histogram, the capacity plan on a small image, and the std/bus surface end to end through a real aura process).
- Test (#5395): the bus SLO and soak lanes. `tests/bench/bus_slo.py` drives a resident host through a fixed traffic pattern and checks the versioned targets (the per-frame p99, the publish rate per CPU second, the largest catchup increment, the handshake cost and the capacity) in CPU time; `tests/bench/bus_soak.py` samples the resource curves (the host's RSS, its descriptors, the coordinator's committed bytes, the loans and the pending trials) while the rounds land, kills the worker periodically to prove the loop recovers and leaves no residue, and fails when a curve grows. The weekly lane (`.github/workflows/bus-soak-weekly.yml`) runs the SLO and then the soak for 24 hours.
- Bus (#5397): the target extension and the reproduction package. A candidate may now rewrite two or three pure policy functions at once (choose-fn + admit-fn + ttl-fn): the peer asks the host for its define names and node ids with `bus:defines` (the node ids live in the host's own workspace AST, so guessing them from another process is not sound), publishes one source-carrier patch per function into a single worldline, and the host's KEEP applies the set atomically — one broken body anywhere in the set leaves every function byte-identical. The host declares which functions the loop may evolve with `AURA_BUS_MUTABLE_TARGETS`; a target outside the list is refused like any other. Every KEEP's admission decision now leaves a reproduction package (`bus:repro`): the evidence five-tuple, the held-out windows, the policy snapshot and the coordinator's own verdict, as one JSON line. `aura bus-repro FILE` re-runs the decision offline — the same binary, the same gate math, no coordinator and no live bus — and compares it field by field; a tampered window fails the check. Regressions: `test_bus_multi_target` (three functions in one worldline, the all-or-nothing failure, the allowlist), `test_bus_repro` (the package reproduces; a tampered one does not).
- Bus (#5396): the adversarial peer boundaries. A hostile peer must not take the bus down and must not borrow authority from it; the rule is that the offending session is cut off and the others are untouched. A connection that never says hello is dropped at its handshake deadline (the coordinator's poll wakes for it instead of waiting for another peer's event). A session that floods the control plane is cut off at its frame rate quota — a token bucket (a sustained rate plus a burst deep enough for a legitimate bulk publish, so publishing the delivered image's channels in one go is not a false positive). The grant tree is bounded — depth 4, fanout 16, 32 live grants per session — so a peer cannot hand out authority in bulk, and a refused grant is audited on its own. `constraint-write` sessions have a change quota per window, and the constraint set now remembers who installed each rule: an install or a rollback that would drop a rule another session installed is refused (`would relax the protection set`), while a session may still roll back its own rules. Malformed frames — an unknown type, an illegal channel, a truncated body, an oversized length — are digested safely: the host does not crash and the honest peers do not notice. New audit kinds: `RateLimited` (29), `GrantLimited` (30). Host environment: `AURA_BUS_PEER_FRAMES` (the sustained rate), `AURA_BUS_PEER_BURST` (the bucket depth), `AURA_BUS_PEER_HELLO_MS`, `AURA_BUS_PEER_CONSTRAINT_CHANGES`, `AURA_BUS_PEER_CONSTRAINT_WINDOW_MS`. Regression: `test_bus_adversarial_peer` — one honest session attached before the attacks keeps answering through every one of them.
- Test: the bus harness reads exactly up to its marker. One pipe read can carry several lines, and the old reader dropped everything past the marker — so a reply that arrived in the same chunk as the previous one was lost, and the check failed depending on the timing (about one run in eight). The reader now keeps the bytes past the marker for the next read. The coordinator also stops only on a stop() request: the wake bell is a wakeup, not an exit, so a stray write can no longer take the bus down.

## 0.3.1

Cross-process self-evolution closed loop (#5376): three tools — a workspace host, a signal/proposal peer, and an independent judge — attach the same bus concurrently and evolve a single pure policy function end to end, with evidence-gated atomic apply, a mirrored protection set, and a canary observation window. No new syntax. The API is still not stable.

- Bus (#5377): `bus:host` serves multiple peers concurrently. The coordinator runs one poll event loop over the listener, a wake eventfd and every session socket; each `PeerSession` owns its conn_fd, session id, root grant, capability, loan ledgers, staging quota and subscription cursor. Shared state (image, grant tree, worldline ledger, constraints, audit) is advanced only by the coordinator thread, so generation commits stay serialized without locks. A peer crash/EOF reclaims only that session's loans and rolls back only its pending trials — other online sessions are untouched. A commit rings the other subscribed sessions' doorbell eventfd. `bus:grant` delegates a scoped single-worldline keep+rollback to another session; `bus:grant-activate` presents the token to gain the delegated bits (the session keeps its read/publish); `bus:revoke` invalidates recursively. `bus:detach` now sends a Disconnect frame so the coordinator ends the session cleanly. Regression: `test_bus_multi_peer` (three concurrent peers, proposer SIGKILL isolation, unscoped KEEP refused).
- Bus (#5378): KEEP atomically applies the trial's PatchRecord to the host's live workspace AST. A source-carrier patch (`bus:publish-source` appends the candidate define source to the image string table; `bus:publish-patch` with `bus:source-field` names the target define node and the string index) is resolved by the coordinator and applied through `mw:snapshot` → `mutate:rebind` → `eval-current`; any failure restores the snapshot, leaving the workspace byte-identical. The trial binds the host workspace generation at open; a stale baseline (another worldline KEPT first) is refused. Regression: `test_bus_keep_apply` (`(score 5)` → 15 after KEEP; invalid syntax refused with the source unchanged).
- Image (#5379): candidate evidence five-tuple binding. `WorldlineRecord` grows an additive tail (`baseline_gen`, `candidate_hash`, `workload_sym`, `seed`, `verifier_version`) under layout_version 2; the frozen 9-field prefix keeps the v1 schema id, so a v1 (48-byte worldline) image stays readable and the tail defaults to zero. `bus:bind-evidence` binds the tuple to a pending trial; KEEP enforces `baseline_gen == current workspace generation`, `candidate_hash == digest(trial patch bytes)` (FNV-1a, low 62 bits), and nonzero workload/seed/verifier — refusing `stale-baseline` / `candidate-hash-mismatch` / `incomplete-evidence` / `missing-evidence` with a Denied audit. `bus:candidate-digest` reads the coordinator's digest; `bus:evidence` reads the committed tail. Regression: `test_bus_evidence_binding` (matching tuple passes, forged/stale/incomplete refused, v1 image compatibility).
- EDSL (#5380): the bus constraint executable minimal safe subset, aligned with the #5253 protection set. The host pre-registers parameterized predicates `pure-define-only` (candidate bodies reject io-/net-/socket-/ffi/c-func/mutate:/set!/bus: and other effect operators), `target-allowlist` and `metric-floor-bound`; peers install by name under constraint-write, never arbitrary closures. The `std/contract` protected names mirror through the #5317 digest into the KEEP structural gate — touching a protected define is refused before any apply. The constraint context now carries the trial's patch records and source texts so the rules inspect what a KEEP would apply. Regression: `test_bus_constraints_subset` (protected define refused, impure body refused, pure patch passes, constraint-write permission isolation).
- Bus (#5381): canary two-phase commit and automatic degradation revert. `WorldlineState::Canary = 4`; a KEEP with an observation window (`AURA_BUS_CANARY_WINDOW` metric ticks, `AURA_BUS_CANARY_FLOOR`, `AURA_BUS_CANARY_KEY`) enters Canary instead of sealing immediately, holding the prior workspace snapshot. Two consecutive below-floor samples auto-revert (restore the snapshot, `canary-reverted` audit); a full at/above-floor window seals to Kept; a judge `bus:rollback` or `bus:canary-confirm` reverts/seals early. At most one active canary — a second KEEP is refused `canary-active`. Defaults off keep the v0.3.0 one-shot KEEP. Regression: `test_bus_canary_rollback` (auto-revert restores the workspace, window seals, concurrent canary refused).
- Test (#5382): three-process closed-loop end-to-end integration and fault-injection matrix. Host + proposer + judge attach the same bus concurrently; the normal path delegates a scoped grant, the judge KEEPs, the canary seals, and the host's policy improves. Five fault classes: proposer SIGKILL (pending worldline rolls back, host survives), judge crash (fail-closed, no auto-apply), forged/stale evidence (refused), unauthorized KEEP (permission) and protected/impure patch (constraint-rejected), backpressure probe. Audit replay reconstructs the worldline lineage. Regression: `test_bus_closed_loop_e2e`.

Not in this version:

- Cross-host transport (TCP/RDMA/CXL), meta-layer evolution, native C/KIR kernel hot-swap (v0.4.0 #5177–#5184).
- API stability (still pre-1.0).

## 0.3.0

Platform release: the workspace bus becomes a shared multi-peer host — one sealed image persists across peer sessions, incremental reads work, and channel capacity follows the delivered image — while module requires get a content-keyed disk IR cache. Long runs stop growing: the boxed-float pool is reclaimed, and the IR fast path survives workspaces with more than 64 lambda defines. No new syntax. The API is still not stable.

- IR specialize (#5388): a workspace with more than 64 lambda defines keeps the IR fast path. `specialize_workspace_lambdas_via_ir`'s whole-workspace pass returned before specializing ANY name when the define count exceeded `kWorkspaceSpecializeCap` (64), so every define — even the first 64 — stayed on the tree walker. aura-runner's physics module (66 lambdas + 29 values) measured `ir-calls=0`; a trivial `(define (probe p i) (list-ref p i))` IR-compiled after 63 sibling defines and fell back after 64, content-independent. The cap is a cost bound on the two-pass O(n) lowering, not a correctness limit — each define still passes the per-define rest/set!/while/free-name gates. The default is now 512, overridable via `AURA_WORKSPACE_SPECIALIZE_CAP` (0 disables the full-workspace pass, the pre-fix escape hatch). Measured on aura-runner's physics: `ir-calls` 0 → 1.58M per 2-course kernel, steady-state 3000ms → 1890ms, golden digests byte-identical; the aura-perf gated round's held-out drops ~2300ms → ~1600ms. Regression: `workspace_source_ssot_2920.aura` case "workspace over the old 64-define cap keeps the IR fast path" (66 and 200 lambdas; fails on the pre-fix binary).
- Test (#5324): the `string_replace` dense-replace linearity probe measures CPU time (`/proc/self/stat` utime+stime ticks, batched reps) instead of wall-clock `monotonic-ms` best-of-N, and builds its inputs once outside the timed window. The wall-clock probe kept failing "dense replace is linear" under loaded parallel CI waves even at best-of-5 (run 44925658024): preemption inflates every sample and the small-size baseline collapses to the 1ms floor, misfiring the ratio checks. CPU ticks are immune to scheduler preemption; a genuinely quadratic replace still fails the ratios (verified ~9.5x/13.5x per 4x size). The algorithm assertion (output equality) is unchanged.
- Module/workspace (#5384): a module define with the same name as a workspace define no longer clobbers the workspace's canonical source row. `cache_module`/`compile_module` recorded the WHOLE module text under the name; the specialize pass scoped lowering to the named define but the #4621 rest gate read the FIRST root define, so a rest-param workspace define was IR-published from the module and its closure resolved to a sibling function — "invalid closure reference" / a foreign arity after a rebind (aura-perf's autopilot round on aura-runner died at the verdict). The source row is now kept for workspace defines, and specialize scopes every guard to the named define. Regression: `test_module_workspace_source_clobber` in the module/query batch.
- Runtime (#5389): the boxed-float pool's reclaim side tables (`g_float_tenants` / `g_float_on_freelist` / `g_float_free_list` / `g_float_mint_serial` / mint serial) are `inline` variables, so every DSO that links `aura_jit_runtime.cpp` shares one instance. They were anonymous-namespace definitions: each DSO got its own copy, the pool accessors resolved to one copy while the reclaim pushed to another, and the free list's buffer growth corrupted an adjacent C-heap block (`corrupted size vs. prev_size while consolidating` / `double free or corruption (!prev)` — `test_hash_table_grow` and `test_misc_issue_fold_batch` aborted with rc=134 on the full-tier issues lane). Single-DSO `aura` runs were unaffected. Verified: both tests green from the repo root (145/145 and 26/26 members), repeat runs clean, bus suite green.
- Reclaim: the boxed-float pool is no longer append-only. Every general-path float op (the tree-walker / IR interpreter, and the JIT rebox points) boxes a double into the process-global `g_float_pool`; before, only `aura_reset_runtime` (session reset / exit) ever cleared it, so a long run's RSS grew linearly with total float ops — a runner that stays up for minutes stuttered as the pool climbed. The file-mode and tree-walker reclaims now mark the float slots live values reference (a boxed float is a leaf index, marked like a string slot) and release the dead ones onto a pool free list that `aura_alloc_float` reuses, the same shape as the string-heap and hash-table slot reclaim. Ownership is stamped per slot at mint (`aura_jit_float_owner_tenant`, falling back to the thread's query-evaluator so a pure `set-code`/`eval-current` program still stamps its own tenant); a reclaim releases only slots its own Evaluator minted, so a second serve session never loses a box it holds. A mint-serial handshake protects newborn slots, and the float-literal intern (`float_intern_by_node_`) is rooted so a cached literal box is never released under the cache. Float mints charge the file-heap reclaim window so a float-only loop that defeats the #5302 raw-double fast path still reaches the trigger. The #5302/#4522 unboxed accumulator paths are unchanged (they never box per step). Verified: a general-path float loop that leaked ~16MB RSS per 2M ops now stays flat over 40M ops; the physics golden, play-review, coin-placement digest, and the `test_value_tag_hotpath_batch` AC7 float-churn assertions are unchanged.
- Bus (#5385): incremental channel reads work. `ChannelBody` gains `total` (ABI minor 1): `count` is now the reply range's record count, `total` the channel's committed count — the next cursor. Before, an incremental `bus:query` decoded zero rows (the bridge derived the element size from total/range) and aura-harness's cursor polling silently lost every new metric/verdict. A cursor ahead of the section generation or count rebuilds to a full snapshot instead of slicing by count; `(0,0)` stays the explicit full read and gen-0-with-count slices by count. `channel_read` follows the same rule. Regressions: `test_bus_channel_transport` (range/total, count-only, ahead-generation), `test_bus_channels`, `test_bus_stdlib`, `test_bus_host` case 6.
- Bus (#5386): `bus:project-cct`'s static projection is a once-per-session snapshot like the live path — a repeat call returns the published count instead of appending the same CCT again (which doubled hotspot samples and burned the channel's capacity). Regression: `test_bus_stdlib` and `test_bus_host` case 6.
- Bus (#5387): `bus:host` channel capacity scales with the delivered image — every channel keeps at least 4096 records and the space beyond that floor is split evenly across the five channels, instead of a fixed 4096 that left ~255 MiB of the default image unused and hard-failed long runs with `image-full`. Exhaustion stays a hard error; nothing grows after attach. Regression: `test_bus_host` case 6 publishes 4200 metrics on the default image.
- Bus (#5383): a rejected attach no longer stops the host. Unknown role, wrong workspace, schema/uid mismatch or a mid-handshake EOF ends that connection only — `accept_one` closes the rejected socket and the serve loop keeps accepting; only a stop request or a dead listener ends it. Before, one misconfigured peer wedged the whole workspace bus (socket alive, `bus:host?` active, every later attach hanging on an unanswered Hello). Regression: `test_bus_host` case 5 — badrole/wrongws/raw-EOF rejections each followed by a legal peer that attaches, publishes and detaches.
- Bus (#5128): the host image persists across peer sessions — one bus, one workspace, one live image. The first attach creates and seals it; every later peer is handed the same memfd, so the next tool reads the previous tool's committed CCT/metrics/patches/worldlines and the shared audit. Disconnect withdraws pending trials and loans, never committed evidence; unhost releases the mapping. Publish-time validation now enforces the attach invariants (patch node inside the node section, metric keys are legal immediates), `bus:project-nodes` emits batch-index edges with no symbol references, and the coordinator projects its trial ledger (pending + final verdict states) into the worldlines channel for subscribers. `test_bus_host` covers three sequential peers: perf publishes and installs a constraint, harness reads the same image and audit, maintainer's KEEP is gated by perf's constraint.
- Module loading (#5374): the require path now uses the content-keyed disk IR cache that `compile_module` already had — `cache_module` reads `$XDG_CACHE_HOME/aura/modules/<path>_<hash>_<build-sha>.abfc` on a hit and skips per-define lowering, and writes the lowered bundles on a miss. Warm requires of the same content behave identically (string-literal pools included); a source or build change keys a new file. Regression: `test_module_disk_cache` in the module/query batch.

Not in this version:

- Debugger and DAP, semantic tokens, inlay hints, tree-sitter grammar, TCP mode, MELPA/ELPA publication.
- macOS, Windows, and other Linux distributions.
- API stability (still pre-1.0).

## 0.2.7

Developer-experience release: `aura lsp` becomes a daily-usable language server, and Doom Emacs gets a one-line `:lang (aura +lsp)` integration. No new syntax. The API is still not stable.

- LSP protocol (#5258): the server is split into transport, position, document, diagnostics and handler layers. It negotiates `positionEncoding` (utf-8 or utf-16), keys documents by normalized path so Emacs-style URIs (unescaped `+ @ :`, raw UTF-8, uppercase `%XX`) resolve to one buffer, publishes debounced diagnostics after `didChange` and answers pull diagnostics, clears them on `didClose`, returns `-32700`/`-32600` for malformed input, survives `initialize` without an id, reports the real binary version, reads `rootUri`/`workspaceFolders`, and resolves `AURA_PATH` and `std/` with the runtime's own module search.
- Symbol layer (#5259): indexing is built on the reader's form spans instead of text search. Comments and strings can no longer define a name, `define`, `define-hygienic-macro`, `define-type` and `define-struct` are covered (`define-syntax`/`define-record-type` are not, they do not exist at runtime), nested defines are children of their scope, and `documentSymbol`, `workspace/symbol`, `foldingRange`, `selectionRange`, `documentLink`, `documentHighlight` and local binding goto work.
- References and rename (#5260): references follow the binding, so a name defined in a required file is visible to its requirers and not the reverse; comment/string text and shadowed locals stay out.
